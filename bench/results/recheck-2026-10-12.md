## Measurement policy

A start requires two checks five seconds apart. The one-minute load must be
below 3.0, with no visible compiler or build process. A check runs every second
during measurement. The campaign retains each observed load and build process.

These checks do not establish exclusive access to the virtual machine. Other jobs
remain active. Host power and thermal state are not observable. A competing
build invalidates the whole metric, with one repeat after a quiet start.
Both attempts and all sample rows remain available.

The primary command metrics use five warmups per version. Each version has
20 paired blocks of five measured runs. The comparison preserves the original
block IDs and uses a 99% bootstrap interval with 10,000 resamples.

The pseudo-terminal metrics use the current executable alone. Each keyboard
series contains 10,000 events. Each CPU series has two five-minute windows.
Memory series use one warmup and four blocks of three runs.
For declared terminal and resource confirmations, the baseline precedes the
candidate in separate full-policy series. These have no paired regression estimate.
A shortened or fully excluded series cannot pass.
